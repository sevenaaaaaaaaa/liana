# 松萝全平台统一设计语言 v1

> 单一事实源：六端（macOS/Android/iOS/Linux/鸿蒙/Windows）的视觉与交互全部对齐本文档。
> 基准取自 macOS 端 Liquid Glass 候选窗（v0.1.0 起的用户心智）。
> iOS build 7 起，颜色、动效与工具入口以 [iOS 体验规范](IOS-EXPERIENCE.md) 为准，采用用户要求的雾白／石墨黑；不改变其他端的颜色。

## 1. 视觉 Token

| Token | 值 | 用途 |
|---|---|---|
| `bg` | `#1C1C22` | 键盘/面板底色 |
| `key` | `#2A2A33` | 普通键 |
| `keyPressed` | `#33333E` | 候选条目 / 按下态 |
| `text` | `#E8E8EC` | 主文字 |
| `secondary` | `#9A9AA5` | 组合中提示 / 次要文字 |
| `accent` | `#337BFF` | 品牌强调（选中态/光标/开关） |
| `radius.window` | `18` | 候选窗/面板整体圆角 |
| `radius.key` | `8` | 按键圆角 |
| `font.candidate` | `17` | 候选字号 |
| `font.key` | `16` | 键帽字号 |
| `keyHeight` | `44–48dp` | 移动端键高 |

## 2. 交互契约（六端一致）

| 操作 | 行为 |
|---|---|
| 空格 | 有候选 → 上屏首选；无候选 → 上屏空格 |
| 数字 1–9 | 选对应候选 |
| 回车 | 组合中 → 原样上屏；空闲 → 换行/确认 |
| 退格 | 组合中 → 回退一码；空闲 → 删除已上屏一字 |
| Esc | 取消组合 |
| 单按 Shift / 中键 | 切换 中/英 |
| 候选 | 至多 9 个，横向排列 |

## 3. 移动端 / Pad 触控创新（本文档定义，Android/iOS/鸿蒙实现）

触屏没有物理按键的"节奏感"，松萝的触控层围绕三个原则设计：
**拇指可达、手势省程、反馈入肉**。

### 3.1 触觉反馈（所有按键）
- 每次按键 `KEYBOARD_TAP` / light impact 触觉；
- 候选上屏（含手势上屏）加强一档反馈，形成"上屏了"的身体确认。

### 3.2 候选上滑直上屏
- 候选条目上滑（≥ 24pt）→ **该候选立即上屏**，不必移到候选词位置点击；
- 这是"眼睛看词、拇指一甩"的高频路径，比点击少一次落点瞄准。

### 3.3 退格双势
- **长按** → 连删（65ms 节奏，先慢后快不变，保持可预期）；
- **左滑** → 整段组合清除（相当于 Esc 的退格版），误打整串拼音时一次手势解决。

### 3.4 Pad 分体键盘（宽度 ≥ 600dp 自动启用）
- 键盘左右分体，中缝留空，两半各自向对应拇指收拢；
- 目的：双手持握平板时拇指不必横跨整个键盘；
- 中缝区域后续承接悬浮工具（数字轮/方向键），本版仅留空。

### 3.5 统一禁用手势
- 不做键盘整体拖动换行（与系统手势冲突）；
- iOS 已按用户需求提供全拼与英文滑行；其余平台按各端实现范围提供。滑行与普通按键区域区分，不阻塞触控处理。

## 4. 桌面端（macOS/Linux/Windows）

桌面无触控层，交互契约（§2）不变；视觉 Token 仅作用于自绘候选窗/面板，
系统级控件（菜单栏图标、安装器）遵循各系统 HIG 优先。
