# ADR-0011：纸偶桌宠——自有开放格式，图片即形象

状态：已接受（2026-10-18）

## 背景

VRM / Live2D 视觉上限高，但可用资源少：好看的模型大多有版权争议或禁止再分发，Live2D 运行时还是专有授权
（见 ADR-0009）。用户想要的是「用自己喜欢的人物 / 自己画的 / AI 生成的几张图就能做出桌宠」，并能分享、
形成社区。ADR-0007 规划过「分层 sprites + 动画系统」，一直没落地。

## 决策

新增渲染器 `puppet`（纸偶），格式规范见 [`docs/pet-puppet-format.md`](../pet-puppet-format.md)。

1. **图片即形象**：1 张图靠网格形变就能动（呼吸、摇摆、歪头、弹跳、挤压回弹、被拎起来摆动）；
   多张图按表情交叉淡入，提供闭眼图即可眨眼。
2. **骨架只有三个点**：脖子转轴、头部范围、脚底线。真人照片由 Vision 人脸框自动推算，
   卡通形象用默认比例，形象工坊里拖动修正。
3. **本机处理**：抠图用 Vision（macOS 14+ 任意主体，12+ 人像分割），图片不出本机。
   AI 生图只提供提示词模板，不内置云端调用。
4. **动作是数据**：关键帧 / 波形作用在固定通道上，叠加求和；触发器与状态映射可被形象包覆盖。
   形象包只含图片与 JSON，导入时按白名单校验，不执行任何包内代码。
5. **渲染器用 JS + WebGL**，跑在 WKWebView 里，复用 VRM / Live2D 的 `window.pet*` 桥：
   同一个 `.lianapet` 将来可直接在 iOS / Android / 鸿蒙的 WebView 里渲染。
6. **分享门槛**：导出 `.lianapet` 需作者声明图片原创或已获授权；用他人照片的形象默认仅个人使用。

## 后果

- 视觉上限低于 Live2D（没有分层物理、口型），但资源门槛最低、无授权风险。
- P2：眼睛 / 嘴巴分层（眨眼与说话口型不再需要整张闭眼图）、可视化动作编辑器、社区目录与投稿流程。
