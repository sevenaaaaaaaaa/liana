# ADR-0015：语言选择层（脚本判定 + 候选合并 + 按语言记票）（2026-11-24）

状态：已接受（M2/M3 实施中）

## 背景

M0 把语言包注册表做出来了，但引擎仍只按当前语言解码：拼音模式打 nihon 出不了
日本，日文模式打 nihao 出不了 你好；app_mode 只有 zh/en 两档，ja/ko/es 无处记票。
M3 又新增了韩语（直打）与西语（变音符），需要一套不改 match 的注册与选择机制。

## 决策

1. **脚本判定**（crates/engine/src/script.rs）只做罗马字语言：
   - 拼音：贪心切合法音节，覆盖率 = 覆盖字符 / 总字符；
   - 日文：罗马字转假名成功 0.55；假名整词命中词典 1.2；前缀命中 0.85；
   - 英文：整词 0.75，前缀 0.55。
   当前语言有 0.1 先验；切换要求对方 ≥0.75 且领先 0.2。
   保护规则：日语切换要求输入 ≥3 字符；≤4 字符且拼音能完整切分时不切
   （gao 是「高/好」，不是「顔」）。
2. **候选合并**（Session::merge_detected_language）：外语候选只用前 3 条，
   分数归一化到当前语言首选附近（top + delta - rank*0.1），不直接比较两套
   打分尺度；命中日文时预编辑串切成假名，不改语言状态。
3. **app_mode 按语言记票**：Entry 从 {zh,en} 改为 lang→score 的 BTreeMap；
   判定仍要求胜方 ≥2.0 且对第二名 ≥2 倍。TSV 每行一语言，旧 6 列「中/英票」
   格式继续可导入；FFI 保留旧 bool 接口，新增 observe_lang / decide_lang。
4. **新语言包**（ko/es）只实现 LanguagePack + 在 builtin_packs 注册一行；
   引擎没有任何 match 分支按语言名分发。

## 备选方案与否决理由

- 所有语言包同时解码、按原始分数合并：各包打分尺度不同（拼音 ~10、日文 ~10 万），
  必须归一化；且每键都跑全部语言会拖慢延迟。
- 用分类器模型做脚本判定：没有训练数据，模型体积也超出 M2 的预算。
- app_mode 保持两档、ja/ko/es 都记到 en：会把日语偏好误判成英文，用户切回中文时行为错。

## 后果

- 混输评测按空格分段（段内不切语言）：50 句语料实测 100%，但语料是本项目手写的、
  与实现同期完成，不等于独立基准；真实混排（一个词内中日交替）仍未支持。
- 短拼音音节（≤4 字母）不会被日语抢走；日文整词（sensei/gakusei）能正确切换。
- 平台侧：macOS 菜单由 LianaMode.allCases 自动出现 ko/es，Info.plist 增加两个输入源；
  Android/鸿蒙/Windows/iOS 仍待 M4 收敛。
