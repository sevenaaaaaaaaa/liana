# ADR-0008：知你（Know-You）自进化框架——从群体先验到个人后验

状态：E0–E4 全部落地 · 日期：2026-09-23

## 一、问题本质：`xian` 为什么永远调不对

输入 `xian`，候选有 现 / 先 / 县 / 线 / 限 / 献 / 西安 / 咸……

- 云输入法的答案：拿几亿人的词频算一个**群体最优**——大多数时候是「现」。
- 但真实场景：
  - 你在终端敲 `xian` 大概率是拼音打错了，想要的是英文或先手命令；
  - 你在写政务材料，最近一周满屏「县政府」「县级市」；
  - 你在和朋友约旅行，上一句是「十一去」——想要「西安」；
  - 你刚打完「优」——Viterbi 词法上下文知道该是「优先」的先。

**群体频率在结构上不可能回答这些问题**，因为答案不在人群里，在「你 + 此刻的上下文」里。
这就是自进化的靶心：**不打扰用户的前提下，把每一次选词与纠错都变成教学信号，
在本地把"群体先验"修正成"你的后验"。**

## 二、核心论点

> 大数据模型 = 群体先验（准，但永远不是你）
> 知你框架 = 群体先验打底 + **个人后验在线结晶**（每个上下文维度独立结晶你的偏好）

三个"别人没有"：

1. **纠错即教学**：云输入法把你的删除当噪声丢弃；我们把「选了又删、删后再选」
   当成最强信号——一次负奖励直接压低该词在该上下文的票，一次重选直接抬升。
2. **喂食式主动学习**：截图/文档拖进来，端上 OCR（Apple Vision，零网络）提炼
   专有名词进"营养库"——教一次，处处可用。大数据模型学不了你的甲方名字。
3. **可解释的决策轨道**：每个候选为什么排前，可以一句话说清
   （"你在 VSCode 最近 3 天 80% 选了先"）——大数据模型是黑盒，我们是账本。

## 三、六层架构

```
┌─ 评估层 E ─ 纠错率/首选命中率/重选率的自对比闭环（周报进傍晚小结）
├─ 代谢层 M ─ 指数衰减（14 天半衰）+ 置信门槛 + 探索保底 + 容量淘汰
├─ 喂食层 F ─ 截图/文档 → 端上 OCR → 术语提炼 → 营养库（带出处、可一键忘记）
├─ 教学层 T ─ 选词=+1 · 重选=+1.5 · 选后删除=−2（最强信号）
├─ 决策层 D ─ 上下文赌动机：score' = base + Σ_dim 亲和度(dim,词)·权重，封顶防劫持
└─ 感知层 P ─ 上下文信号栈：词法窗 / 应用 / 时段 / 主题指纹 / 会话 / 营养库
```

### 感知层 P：信号栈（全部已具备或低成本可得）

| 维度 | 信号 | 现状 |
|---|---|---|
| lex 词法 | 最近上屏的 4 个字 + 2 字 bigram | Viterbi 已有会话内，扩到跨句 |
| app 应用 | bundle id | 按应用记忆已在用 |
| tod 时段 | 早/午/晚/夜 四桶 | 免费 |
| topic 主题指纹 | 最近 32 字特征哈希 → 16 桶取 top3 | 零模型，纯哈希 |
| feed 营养库 | 喂食提炼的词与强度 | E2 落地 |

### 决策层 D：上下文赌动机（创新核心，E0 已实现）

每个候选词 w 的最终分：`score'(w) = base(w) + clamp(Σ_f A(w,f), −3, +3)`

- `A(w,f)`：词 w 在特征 f 上的**指数滑动平均亲和度**（半衰期 14 天，同 app_mode）；
- 置信门槛：`n(w,f) ≥ 2` 才参与（两次观察以内不说话，防单次误选劫持）；
- 总修正封顶 ±3：学习永远只能"微调排序"，不能掀桌（base 分仍是词频与整句概率）；
- 探索保底：修正后排名第 2+ 的候选保留原位展示，用户随时可用数字键"越级纠错"。
- **一次纠正就记住（短语层）**：在同一个按键串上明确选了非首选词时，把「按键 → 词」记进短语库，
  下次同一个按键串直接首选该词。这条不走 ±3 的赌动机上限——它不是猜偏好，而是用户亲手指定；
  改选别的词会一次覆盖旧选择，不会越改越乱。

### 教学层 T：信号强度分级

| 行为 | 奖励 | 理由 |
|---|---|---|
| 正常选词上屏 | +1.0 | 弱正（可能只是顺手） |
| 选后 N 秒内删除重选别的 | −2.0 | 强负：明确打脸 |
| 删除后重新选中的词 | +1.5 | 强正：纠正后的真实意图 |
| 数字键选了第 2+ 候选 | +0.6 | 补充正：排序还不够准 |

### 喂食层 F：主动学习通道

菜单「喂它一段」→ 截图 / 拖文件 / 粘贴文本 → Apple Vision 端上 OCR →
术语提炼（2–6 字 n-gram 复现 ≥2 次 + 停用表过滤）→ 营养库
`词 → {出处, 强度, 时间}`。营养词获得：用户词典级注入 + `feed` 维度亲和度。
营养库在权限中心逐条可见、可忘——**吃什么、记住什么、忘掉什么，全由你**。

### 代谢层 M：遗忘与稳定

- 一切亲和度按 14 天半衰衰减（换项目后旧词自然淡出）；
- 观察数 < 2 不参与；总修正封顶 ±3；
- 容量 5 万条 (词,特征) 对，超出按最久未触摸淘汰；
- 全部数据 = 本地 TSV，可导出（进加密备份）、可清空。

### 评估层 E：自我对比闭环

现有统计（纠错率、删除次数）扩展两项：**首选命中率**与**重选率**。
每晚小结自动对比："学习开"的实际纠错 vs 打分时剔除学习项的**反事实纠错**——
差值就是今天学习的收益。周报告诉你：这周知你让纠错率从 8% 降到 5%。

## 四、隐私边界（不可谈判）

1. 全部信号、亲和度、营养库只在本机；TSV 明文仅存在于加密备份内；
2. 不上传任何东西——没有"改进服务"条款，没有匿名遥测；
3. 决策可解释：菜单里随时能问"为什么是它"；
4. 一键清空（权限中心），忘了就是真忘了。

## 五、落地路线

| 阶段 | 内容 | 状态 |
|---|---|---|
| E0 | 决策层内核骨架：特征哈希 / 亲和度 EMA / 奖励 / 封顶 / 导出 / 解释（纯逻辑 + 单测） | ✅ 本 ADR 附带 |
| E1 | 教学层接线：InputController 捕获选词/删除/重选序列 → 奖励；候选排序接 adjust | ✅ 账本为 FFI 进程单例（跨应用共享）；adjust 只在「同 literal 层 + 同 consumed」等价层内重排，覆盖分层不变式不破；删除窗口 10s、重选窗口 30s；账本随 userdata.enc（schema v2）加密落盘，菜单可开关/清空 |
| E2 | 喂食层：Vision OCR + 术语提炼 + 营养库 + 权限中心管理 | ✅ 术语提炼 = 汉字段内 2–6 字 n-gram 复现 ≥2 + 停用表 + 长词覆盖剪枝（纯统计零模型）；营养词获得词典级加分 +3+ln(强度) 与按键召回（按键串由词典单字最高频读音派生，缺字词只加分不召回）；喂食窗 = 文件/剪切板截图/粘贴 + Vision 端上 OCR（零网络，UTF-8/GB18030）；营养库随 userdata.enc（schema v3）落盘，喂食窗与权限中心逐条可见可忘；忘记即加分与召回全部消失 |
| E3 | 评估层：命中率/重选率统计 + 傍晚小结收益报告 | ✅ 每次选词产出反事实评估：`SelectionEval {实际首选命中, 基线首选命中(重排前顺序快照), 重选, 越级}`，与学习开关解耦（关闭时基线=实际，收益读作 0）；PetStats 日账新增 selections/top1/baseTop1/reselects（旧档兼容解码）；傍晚小结加「首选命中 X% · 重选 N 次」与「🎯 知你学习：首选命中比无学习高 D 个百分点」收益行 |
| E4 | L2 增强：本机 Gemma 提炼喂食文档的术语与主题（仍零云） | ✅ 复用同传的 llama-server（回环 HTTP，串行队列）+ Gemma 3 270M：统计提炼打底后，AI 补一轮专有名词（一行一词、2–6 字含汉字、去重封顶 20，与统计结果去重后并进同一勾选流，标「AI」）+ 一句主题概括（进营养词出处元数据）。开关默认仅在运行时+模型齐备时打开，统计提炼永远可用作回退；决策始终走账本，Gemma 只增强感知 |

## 六、为什么这是创新的

- ** vs 云输入法**：它们优化"平均人"，我们收敛"你"；它们需要你的数据上云，我们
  连 WiFi 关了都照常进化。
- ** vs 大数据词频**：词频是静态先验；亲和度是随你漂移的动态后验（项目换、话题换、
  时段换，排序跟着换）。
- ** vs 端侧大模型**：大模型单次推理贵、仍不可解释；赌动机是账本式的——纳秒级、
  可解释、可审计、可回滚。两者不对立：E4 用大模型增强感知，决策始终走账本。

## 后果

- 好处：越用越准且**越用越是你**；隐私与智能第一次不冲突；每一步可解释可回滚。
- 代价：排序逻辑多了一层需要防劫持的复杂度（封顶/置信/探索保底即为此设计）；
  多端同步时亲和度账本需并入 CRDT（sync crate 已有 LWW 基础）。
