# 松萝 iOS

iOS 15+，UIKit 宿主 App + 本地 Rust 键盘扩展。已通过 iPhone arm64 编译、IPA 结构检查和模拟器键盘行为测试，尚未完成实体 iPhone 验收。

## 构建与安装

需要 Xcode、Rust、XcodeGen、Python 3。设备构建需要 Rust target `aarch64-apple-ios`，Apple Silicon 模拟器需要 `aarch64-apple-ios-sim`（Intel 使用 `x86_64-apple-ios`）。

```bash
./platforms/ios/build.sh device       # 默认；dist/Liana-iOS-<版本>-build<构建号>-unsigned.ipa
./platforms/ios/build.sh simulator   # 仅当前主机架构的模拟器 App
./platforms/ios/build.sh all
python3 platforms/ios/validate_ipa.py dist/Liana-iOS-0.8.0-build7-unsigned.ipa
```

IPA 未签名。用自己的签名安装工具签名主 App 和 `PlugIns/LianaKeyboard.appex`，保留嵌入扩展，确保各自 Bundle ID 与描述文件一致。默认 ID 分别是 `dev.liana.ime.ios` 与 `dev.liana.ime.ios.keyboard`。

安装后打开 App 查看引导，再到「设置 → 通用 → 键盘 → 键盘 → 添加新键盘」添加松萝，输入时长按地球键切换。候选与学习在键盘自己的沙盒中完成，不需要允许完全访问。

### iOS 27 启动要求

使用 iOS 27 SDK 构建的 UIKit App 必须采用 Scene 生命周期，否则 iOS 27 会拒绝启动。build 4 及更早版本缺少此声明；请使用 build 5 或更新版本。宿主通过 `UIApplicationSceneManifest`、`AppDelegate.configurationForConnecting` 与 `SceneDelegate` 创建窗口，文件打开也经场景路由。参见 [Apple 的生命周期迁移说明](https://developer.apple.com/documentation/uikit/transitioning-to-the-uikit-scene-based-life-cycle)。

## 体验重构（build 7）

雾白与石墨黑采用统一文字、表面和反馈色，默认跟随系统。按下即时反馈、松开轻量恢复；工具面板开合与主题切换使用短过渡，尊重系统「减少动态效果」。字母输入的后台解码与候选复用保持。

顶部工具按输入／表情／同步／词库分组，布局先提供标准、单手、宽松预设，再展开精细调节。空闲候选区提供常用标点；首候选突出显示。手机横屏将组合、候选和工具合到一行，保持输入前后的高度一致；平板中间候选复用按钮，光标控制先提交再移动。

主 App 重做首页、工具分类、草稿编辑与 Mac 连接。分类固定在顶部。语音草稿保存在本机，可清空／撤销；停止录音会等待尾句完成，之后可编辑复制。新录音追加到已有草稿。文字与 GIF 可直接粘贴，也可回松萝接收；配对与词库仍只提供专用接收类型。

详见 [iOS 体验规范](../../docs/design/IOS-EXPERIENCE.md)。

## 比例与入口

- 主题只有黑色、白色，默认跟随系统；在比例设置顶部可手动选择。恢复默认也会恢复跟随系统。
- 拖动顶部工具组上下调键高（44–64pt），左右拖动移动整组入口；VoiceOver 提供增高/降低动作。
- 滑块图标打开布局与手感，展开「精细调节」可调整：键高、目标宽度（78–100%，手机最小可用宽度 320pt）、左右位置、候选字号（14–24pt）、额外底部留白（0–24pt，另有固定 8pt 底部间距和 4pt 候选区间距）、入口位置。
- 滑块之外提供加减按钮与恢复默认。调节不清除组合串；设置保存在键盘自己的沙盒，退出或重新调出键盘后保留。
- 宽度与左右位置用于手机单手布局；iPad 分体继续使用屏幕两侧，高度与字号仍可调。
- 顶栏按「语音设备 ／ 剪贴板 ／ 发送文件 ／ 表情 ／ 输入工具 ／ 布局与手感」六个同级图标排成一排（每个 44×44 热区），与原来的波形入口同尺寸；拖动整组仍可调键高与左右位置。剪贴板、表情入口直接打开输入工具面板并选中「同步」「表情」分类；发送文件入口走既有接收流程，没有内容或未允许完全访问时会在面板底部给出明确提示。组合串空间不足时先收起「清空」按钮，避免与入口重叠。
- 九键有两种形态，在「布局与手感」面板的「九键布局」里切换，保存在键盘自己的沙盒：
  - **九键 · 侧栏（默认）**：中间是标准 3×3（1–9 带字母），左右两列更窄——左列放符号 `，。？！`（`？！` 键长按可选 `！、@、#`），右列放 `⌫`／`⏎`／`清空`；底行放 `中`／`🌐`／`空格`（双宽）。两列窄于主键，整组不超出键盘宽度，所有键高 ≥44pt。
  - **九键 · 经典**：中间 3×3，每行右侧一个附加键（`⌫`／`清空`／`，`），底行 `🌐`／`中`／`空格`／`⏎`。

## 输入方案与移动工具（build 6）

- 长按底部「中／EN」或点顶部四格 → 输入方案：全拼、九宫格、小鹤／微软／自然码双拼、五笔 86、离线手写。点按中／EN 仍切换中英文。
- 微软双拼的 ing 使用底部 `;` 键。五笔使用 Rime 86 字词表；九宫格按完整拼音的数字序列匹配与补全，例如 `64426` → 你好；长数字串按分段组合给出整句候选，例如 `5468426842674` → 今天天气。九宫格组合态的顶栏显示拼音音节（例如 `jin tian tian qi`）而不是内部数字串；还原不出拼音时显示「九宫格」。
- 全拼与英文支持字母间滑动，抬手后选词；这是本地几何轨迹匹配的首版，尚未加入个性化轨迹训练。当前不支持双拼或五笔滑行。
- 手写在画布内按笔顺写单字，候选栏选字；支持撤销一笔、清空、删除。识别器及模型随包携带，无需联网。
- 颜文字在顶部四格面板直接插入。主 App「语音 · 词库 · GIF · 剪贴板」选择本地 GIF，复制到键盘后点四格 → 接收 App 内容；键盘中点缩略图复制，再在支持图片的 App 粘贴。最多保存 12 个，每个不超过 4MB；可清空。不提供在线 GIF 搜索或跨 App 直接发图。
- 语音在主 App 点击开始录音，仅使用设备端 Speech 识别：支持中文、英语、日语、韩语、俄语、法语、西班牙语七种语言，选择会记住；某语言离线语音包未安装时会提示系统安装路径，不会改用云端。打开同声传译后，识别时边说边显示文字，并可按目标语言实时生成译文（iOS 18+ 使用 Apple 本地 Translation 框架；语言包缺失时由系统提示下载，iOS 15–17 仅识别文字并提示版本要求）。复制时原文与译文分区一起复制，回键盘四格面板接收并插入；键盘扩展没有麦克风权限，不在后台录音。

### 词库导入

主 App 可选择本地 UTF-8 TXT／TSV／Rime dict.yaml，也可粘贴 GitHub 文件链接（github.com 的 blob 链接或 raw.githubusercontent.com）。选择拼音／五笔类型，后台解析，再「复制已解析词库到键盘」，回到键盘四格 → 接收 App 内容。每次最多 20,000 条、文件最多 20MB；TXT 一行一词会自动转拼音，多音字可用显式拼音纠正。

TSV 格式：`词语<Tab>song luo<Tab>1000`，五笔第二列填五笔码。仅解析词条，不执行 YAML 或远程代码。系统词库在键盘四格 → 导入系统补充词库，使用公开 UILexicon（联系人姓名、文本替换、常用补充词），不包含苹果私有的完整词库与词频模型。

常用短语在主 App 输入工具 → 词库配置后复制到键盘，键盘长按九键数字下滑可用（主 App 最多 20 条、每条 50 字）。

主 App 与键盘通过用户主动操作的本地剪贴板交接，不依赖需要专用描述文件的 App Group，以兼容自行重签。交接内容仅本机保留 10 分钟，不加入通用剪贴板；接收操作需要允许键盘完全访问。学习记录和个人 SQLite 词库在键盘自己的沙盒中持久保存，覆盖升级保留，卸载会清除。

### Mac 文字剪贴板

两端升级，先在主 App 配对 Mac；移动工具 → 复制 Mac 配对给键盘 → 键盘四格 → 接收 App 内容。键盘会将配对保存在自己的钥匙串中。Mac 桌宠收件箱开启接收并勾选「允许已配对设备发送／读取文字剪贴板」（默认关闭）。随后点键盘四格的发送／接收按钮，同一局域网通过已配对 TLS 连接传输最多 4KB 文字。收到 Mac 文字写入 iPhone 剪贴板后，由用户粘贴；不自动插入当前输入框。

这是前台按需同步，不监听系统剪贴板、不进行后台轮询，不同步图片或剪贴板历史。忘记／撤销时可在 Mac 撤销配对并换码。

## Mac 桌宠收件箱

主 App 的「连接 Mac 桌宠 · 发送文件」支持扫码或粘贴配对码，首次在 Mac 允许，后续可直接连接。使用文件选择器发送单个文件，或在文件 App 选择用松萝打开；Mac 校验保存后桌宠提示收到文件。收件箱位于 Mac 下载目录下的「松萝收件箱」，单文件上限 200MiB。发送期间保持 iPhone App 前台。

此功能使用主 App 的本地网络权限，不要求键盘完全访问，不同步输入内容。两端都需要升级。配对、撤销、保存规则与实机验证边界见 [桌宠收件箱](../../docs/pet-link.md)。

## 蓝牙设备（实验）

波形图标打开设备面板。普通输入和布局调节不需要完全访问；BLE 扫描/连接单独要求用户允许完全访问与蓝牙权限。仅点击连接时创建蓝牙管理器，不联网，不发送输入框上下文，不自动执行收到的文本。

HID 设备由 iOS「设置 → 蓝牙」配对并直接输入当前 App。键盘不能代替系统配对、读取系统已配对 HID 列表或截获 HID 事件。

BLE 流程：扫描（15 秒）→ 手选设备 → 选择设备文档指定的 Notify／Indicate 通道 → 接收并预览 → 点击插入。成功订阅后记住设备和通道，可点击「连接上次」。关闭面板、切换输入框或隐藏键盘时停止连接；不承诺后台驻留或自动唤醒。

在「HID 配对说明与 BLE 协议」中选择文字格式：

```text
# UTF-8 行：每条最终识别文字以 LF 结尾，支持通知包拆开 UTF-8 字符
你好\n

# JSON Lines：JSON 对象后跟实际 LF，type 为 partial 或 final
{"type":"partial","text":"你"}
{"type":"final","id":"utterance-1","text":"你好"}
```

JSON 的 `id` 用于单次连接内去重，保留最近 32 个 final ID；partial 只预览。每帧最大 16KiB，待组包缓冲最大 64KiB，待插入文字最大 32KiB；错误或溢出会提示并停止接收。设备必须自行识别语音并提供兼容文字通道；不支持直接传音频、专有二进制协议或自动触发录音命令。设备侧若要求写入启动命令，需要按其协议另行适配。

已验证协议解码和键盘面板行为；实体 iPhone 的蓝牙授权、系统沙盒访问与硬件连接仍待验收，不能将模拟器通过视为设备兼容保证。

## 长按滑动与常用短语（build 8 起，build 9 继续）

工具键已从键盘移除（工具面板只从顶栏四格图标进入）；九键的数字 1 兼作「数字／符号页」切换，九键不再有独立的 `123`。

所有手势都要先按住再滑动，未达时长就松手仍是普通按键：

- **九键数字键 1–9**：长按 1 秒后上滑 → 选该键数字与字母大小写（1 键给数字与常用标点 `，。？！`）；下滑 → 常用短语条；左右滑 → 移动光标（提交待选后 `±1`）。
- **回车键**：长按 1 秒后下滑 → 换行（有组合串先提交，不会多提交一次）。普通点按仍是确认／换行。
- **删除键**：长按 3 秒后上滑 → 清空当前输入（组合串与已上屏文字）；按住期间会提示「继续上滑清空」。普通点按与原 0.3 秒连删不变。
- 前置时长集中在 `KeyboardGestureDefaults`，九键与回车的长按时长可在「布局与手感 → 精细调节 → 手势长按」调到 0.5–2 秒；删除键清空固定 3 秒。

VoiceOver 替代路径：清空用删除键的自定义动作「清空当前输入」或界面上的「清空」键；换行用 `⏎`；短语用工具面板「词库 → 常用短语」；光标用工具面板「输入 → 左移／右移光标」；数字与字母用 1 键切页或 QWERTY。

### 常用短语

默认内置 12 条（好的、谢谢、马上、稍等、在吗、没问题、收到、辛苦了、明天见、晚安、可以的、稍后回复），保存在键盘沙盒的 `keyboard.phrases`。主 App「词库」页编辑后复制，键盘工具面板「词库 → 接收短语」覆盖，交接格式为 `KeyboardPayload(kind: "phrases", text: 每行一条)`；键盘会去空行、去重、限制最多 20 条、每条 ≤50 字，保存后提示「已保存 N 条常用短语」。

## 移动端取舍

构建时分两档，兼顾键盘扩展的内存预算与候选覆盖：

- **core（`Resources/base.ifd`）**：从 `base-large.tsv` 按词频选 10 万条，保留全部单字与常用简拼先验，并合并 `packs/default/*` 人工词包。当前 135,113 词条 / 2.53 MB，供 Rust 会话做整句候选。
- **full（`Resources/mobile.sqlite`）**：合并 `base-large.tsv`（199,776 条）+ `packs/default` + `packs/optional` + `packs/mobile` 的混合拉丁词，同词同音取最大词频去重，生成拼音/五笔/英文回退索引。当前 236,317 条拼音词条 + `tags` 表 27,666 行（place 3,550 / person 24,116），SQLite 40.4 MiB。

词包覆盖常见字词、词组、诗歌名句、人名、地名、生活用品、学科、办公用品、软件/App、AI 词汇、医疗养生、金融、年度媒体盘点与网络流行语；多音字读音逐条校对（银行 hang、重庆 chong、长城 chang、重量 zhong、长大 zhang 等）。不打包桌面神经模型。SQLite 按磁盘页读取，不整体常驻；base.ifd 常驻内存。实体设备内存、不同 App 中的切换与长期使用仍需验证。

候选按四层合并，既保证覆盖也不牺牲整句排序：

1. **本地整串精确命中**：全拼/双拼按全拼 code、九键按 digits 直接查 SQLite，学习次数高与词频高的排前（新词进库即可上线）。
2. **Rust 会话候选**：分词、纠错、简拼、整句重排仍在会话内完成。
3. **分段组合**：还有空位时用 `MobilePhraseComposer` 把输入切成词，按「段数最少 → 词频最高」补候选。
4. **音节兜底**：以上都没有时，用内置合法音节表做 DP 切分，逐音节取单字最高频候选，任何合法拼音输入都不会空白。

分层实现见 `Keyboard/MobileEngine.swift` 的 `refresh()` 与 `PinyinSyllables.swift`；只查本地词库与用户词库，不内置特例词、不联网；九宫格与全拼共用同一套词条。覆盖回归语料 97 条真实输入（生活用品／学科／办公／App／AI／医疗／金融／诗歌／人名／地名／流行语等）：候选空白 0 条，已收录词首候选零错位。

首选排序在四层之上再叠加两类信号，规则见 `MobileEngine.refresh()` 与 `RankingBehaviorTests`：

- **学习权重**：用户选过的词按本机 learned 计数排到同码候选最前，再选别的词即可切回。
- **上下文类别**：mobile.sqlite 的 `tags` 表给词打 place／person 标签；最近上屏尾部是「去／到／在／回／从／往／来／驻／出差到／飞往」时优先地名，是「叫／是／找／老师／同学／同事」时优先人名。例如 `chengdu` 裸打首选仍是「程度」，但上屏「去」之后首选变成「成都」；`xian` 在「在」之后首选「西安」；`lihua` 在「叫」之后首选「李华」。没有触发词时完全不重排，裸打语义仍按词频。
